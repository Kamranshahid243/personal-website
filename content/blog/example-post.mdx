This file documents the authoring contract for `content/blog`. Keep it around
as a living checklist, or delete it once your real writing covers the same
ground.

## Frontmatter

Validated by `postFrontmatterSchema` in `src/lib/content/schema.ts` when the
file is read. A missing `description`, `category`, or a malformed `publishedAt`
fails the build and names this file, rather than shipping an empty `<meta>` tag.

Required fields:

- `title`
- `description`
- `publishedAt`
- `category`

Optional fields: `updatedAt`, `tags`, `draft`, `featured`, `image`.

## What the pipeline gives you

GitHub-flavoured markdown is enabled, so tables, ~~strikethrough~~ and task
lists all work. Headings get `id` attributes and become anchor links
automatically — the article table of contents uses the same slugs.

Code fences are highlighted at build time by Shiki, in both themes at once:

```ts title="src/lib/example.ts" {2}
export function greet(name: string) {
  return `Hello, ${name}`;
}
```

The `title=` attribute renders a filename banner, and `{2}` highlights a line.

## Components

React components can be used inline. Anything exported from
`src/components/mdx/mdx-components.tsx` is available without an import — `Img`,
for instance, renders an optimised `next/image`.
